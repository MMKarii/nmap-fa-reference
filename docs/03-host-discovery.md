# ۳. Host Discovery، کشف میزبان

کشف میزبان، فرآیند شناسایی دستگاه‌های فعال (میزبان) در یک شبکه است.

## `-sn (No Port Scan)`

- **توضیح فنی:** Nmap پس از کشف میزبان‌های زنده، اقدام به اسکن پورت نمی‌کند. اغلب "Ping Sweep" نامیده می‌شود. به طور پیش‌فرض از ترکیبی از ICMP Echo Request، TCP SYN به پورت ۴۴۳، TCP ACK به پورت ۸۰ و یک درخواست ARP (در شبکه‌های محلی) استفاده می‌کند.

- **نوع Packet ارسالی:** ترکیبی از بسته‌های ICMP، TCP و ARP.

- **شرایط موفقیت:** دریافت پاسخ مثبت از حداقل یکی از پروب‌ها.

**مثال عملی:**

```bash
nmap -sn 192.168.1.0/24
```

- **مزایا:** سریع، کارآمد برای نقشه‌برداری اولیه شبکه.

- **معایب:** ممکن است میزبان‌هایی که این پروب‌ها را فیلتر می‌کنند، از قلم بیفتند.

- **سناریوی استفاده:** شمارش اولیه دستگاه‌ها در یک شبکه داخلی.

## `-Pn (Skip Host Discovery)`

- **توضیح فنی:** Nmap مرحله کشف میزبان را به طور کامل نادیده می‌گیرد و تمامی آدرس‌های هدف را زنده فرض کرده و مستقیماً اسکن پورت را روی آن‌ها اجرا می‌کند.

- **نوع Packet ارسالی:** هیچ بسته‌ای برای کشف ارسال نمی‌شود. اولین بسته‌ها، بسته‌های اسکن پورت هستند.

- **شرایط موفقیت:** هدف واقعاً وجود داشته باشد و به بسته‌های اسکن پورت پاسخ دهد.

**مثال عملی:**

```bash
nmap -Pn 10.10.10.5
```

- **مزایا:** مفید برای میزبان‌هایی که به پروب‌های کشف معمول پاسخ نمی‌دهند (مثلاً توسط فایروال مسدود شده‌اند).

- **معایب:** اگر هدف غیرفعال باشد، زمان اسکن به‌طور قابل توجهی تلف می‌شود.

- **سناریوی استفاده:** اسکن میزبان‌های پشت فایروال سخت‌گیرانه که Ping را بلاک می‌کنند.

## `-PE (ICMP Echo Request Ping)`

- **توضیح فنی:** ارسال بسته ICMP Type 8 (Echo Request) و انتظار برای دریافت ICMP Type 0 (Echo Reply).

- **نوع Packet:** ICMP Echo Request.

- **شرایط موفقیت:** دریافت ICMP Echo Reply.

**مثال عملی:**

```bash
nmap -PE 192.168.1.1
```

- **مزایا:** ساده و استاندارد.

- **معایب:** به راحتی توسط فایروال‌ها مسدود می‌شود.

- **سناریوی استفاده:** شبکه‌های داخلی که محدودیت کمتری دارند.

## `-PP (ICMP Timestamp Request Ping)`

- **توضیح فنی:** ارسال بسته ICMP Type 13 (Timestamp Request) و انتظار برای دریافت ICMP Type 14 (Timestamp Reply).

- **نوع Packet:** ICMP Timestamp Request.

- **شرایط موفقیت:** دریافت ICMP Timestamp Reply.

**مثال عملی:**

```bash
nmap -PP 192.168.1.1
```

- **مزایا:** کمتر رایج، ممکن است از فیلترهای ساده ICMP Echo عبور کند.

- **معایب:** بسیاری از سیستم‌ها به طور پیش‌فرض به این درخواست پاسخ نمی‌دهند.

- **سناریوی استفاده:** زمانی که ICMP Echo مسدود است.

## `-PM (ICMP Address Mask Request Ping)`

- **توضیح فنی:** ارسال بسته ICMP Type 17 (Address Mask Request) و انتظار برای دریافت ICMP Type 18 (Address Mask Reply).

- **نوع Packet:** ICMP Address Mask Request.

- **شرایط موفقیت:** دریافت ICMP Address Mask Reply.

**مثال عملی:**

```bash
nmap -PM 192.168.1.1
```

- **مزایا:** بسیار نادر، احتمال عبور از فیلترها وجود دارد.

- **معایب:** پاسخ‌دهی بسیار کم، عمدتاً توسط روترهای قدیمی.

- **سناریوی استفاده:** تست‌های نادر در محیط‌های خاص.

## `-PS (TCP SYN Ping)`

- **توضیح فنی:** ارسال بسته TCP با پرچم SYN تنظیم شده به پورت‌های مشخص (پیش‌فرض ۸۰). اگر پورت بسته باشد، یک بسته RST دریافت می‌شود. اگر پورت باز باشد، یک بسته SYN/ACK دریافت می‌شود. در هر دو حالت، میزبان زنده تشخیص داده می‌شود. اگر هیچ پاسخی نیامد، میزبان احتمالاً غیرفعال است یا بسته فیلتر شده.

- **نوع Packet:** TCP با پرچم SYN.

- **شرایط موفقیت:** دریافت TCP RST یا SYN/ACK.

**مثال عملی:**

```bash
nmap -PS22,80,443 10.0.0.1
```

- **مزایا:** قابل اعتمادتر از ICMP در بسیاری از شبکه‌های اینترنتی، زیرا ترافیک TCP معمولاً کمتر مسدود می‌شود.

- **معایب:** نیاز به ساخت بسته‌های TCP خام دارد (نیاز به دسترسی بالا).

- **سناریوی استفاده:** کشف میزبان‌های اینترنتی که ICMP را مسدود کرده‌اند.

## `-PA (TCP ACK Ping)`

- **توضیح فنی:** ارسال بسته TCP با پرچم ACK تنظیم شده. از آنجایی که این بسته بخشی از یک connection موجود نیست، میزبان‌ها معمولاً با ارسال بسته RST پاسخ می‌دهند.

- **نوع Packet:** TCP با پرچم ACK.

- **شرایط موفقیت:** دریافت TCP RST.

**مثال عملی:**

```bash
nmap -PA22,80,443 10.0.0.1
```

- **مزایا:** می‌تواند قوانین فایروال stateful را دور بزند که تنها connection‌های آغاز شده از داخل را مجاز می‌دانند (چون ACK به تنهایی غیرعادی است).

- **معایب:** ممکن است توسط فایروال‌های پیشرفته شناسایی شود.

- **سناریوی استفاده:** تست عبور از فایروال‌های stateful.

## `-PR (ARP Ping)`

- **توضیح فنی:** ارسال درخواست ARP Broadcast. این تکنیک فقط در شبکه‌های محلی (LAN) کاربرد دارد.

- **نوع Packet:** ARP Request.

- **شرایط موفقیت:** دریافت ARP Reply.

**مثال عملی:**

```bash
nmap -PR 192.168.1.0/24
```

- **مزایا:** بسیار سریع، مطمئن و غیرقابل فیلتر در لایه ۲.

- **معایب:** فقط در شبکه محلی کار می‌کند.

- **سناریوی استفاده:** کشف سریع و دقیق تمامی میزبان‌ها در یک شبکه LAN.

## `--disable-arp-ping (Non-ARP Ping)`

- **توضیح فنی:** 

را مجبور می‌کند حتی در شبکه‌های محلی نیز از تکنیک‌های لایه ۳ (مانند ICMP یا TCP) برای کشف میزبان استفاده کند و از ARP پرهیز نماید.

- **نوع Packet:** بستگی به سایر پرچم‌های کشف دارد (مثلاً ICMP یا TCP).

- **شرایط موفقیت:** دریافت پاسخ لایه ۳.

**مثال عملی:**

```bash
nmap -sn --disable-arp-ping 192.168.1.0/24
```

- **مزایا:** شبیه‌سازی رفتار اسکن از راه دور روی شبکه محلی.

- **معایب:** بسیار کندتر و کمتر قابل اعتماد از ARP در LAN.

- **سناریوی استفاده:** تست اثربخشی قوانین فایروال میزبان در شبکه داخلی.
