# ۹. Firewall / IDS / IPS Evasion

این تکنیک‌ها برای کاهش احتمال تشخیص و مسدود شدن اسکن طراحی شده‌اند.

## `-f (Fragment Packets) و --mtu`

- **تحلیل فنی:** بسته‌های پروب (عمدتاً TCP header) را به تکه‌های کوچک‌تر تقسیم می‌کند. هدف این است که سیستم‌های تشخیص نفوذ که بر اساس الگوهای کامل بسته کار می‌کنند، نتوانند ترافیک اسکن را شناسایی کنند.

- **نوع بسته:** بسته‌های fragmented IP.

- **نقاط ضعف:** بسیاری از فایروال‌ها و IDS/IPS مدرن قادر به reassemble کردن تکه‌ها هستند. همچنین ممکن است باعث مشکلات عملکردی در شبکه یا میزبان هدف شود.

- **ریسک‌های عملی:** افزایش چشمگیر تعداد بسته‌های ارسالی.

**مثال:**

```bash
sudo nmap -sS -f 10.0.0.1
```

- **--mtu:** اجازه می‌دهد اندازه واحد انتقال حداکثر (MTU) به صورت دستی مشخص شود (باید مضرب ۸ باشد). مثال: --mtu 24.

## `-D (Decoy Scan)`

- **تحلیل فنی:** آدرس‌های IP جعلی (Decoy) را به همراه آدرس واقعی خود در مبدأ بسته‌ها قرار می‌دهد. از دیدگاه هدف، اسکن از چندین منبع به طور همزمان در حال انجام است که تشخیص منبع واقعی را دشوار می‌کند.

- **نوع بسته:** بسته با آدرس مبدأ جعلی (Spoofed Source IP).

- **نقاط ضعف:** اگر Decoy‌ها زنده نباشند، پاسخ‌های آن‌ها (مثل RST) به هدف نمی‌رسد. همچنین، ترافیک از سمت Decoy‌ها به سمت شما بازمی‌گردد که ممکن است باعث مشکل شود (اگر در مسیر باشند). تحلیل ترافیک خروجی از هدف می‌تواند منبع واقعی را فاش کند.

- **ریسک‌های عملی:** ممکن است باعث ایجاد ترافیک ناخواسته به Decoy‌ها شود و مسائل قانونی ایجاد کند. هرگز از آدرس‌های IP متعلق به سازمان‌های دیگر به عنوان Decoy استفاده نکنید.

**مثال:**

```bash
sudo nmap -sS -D RND:10,ME 192.168.1.10
```

(۱۰ آدرس تصادفی به علاوه آدرس واقعی)

## `-S (Spoof Source Address) و -e`

- **تحلیل فنی:** آدرس IP مبدأ بسته‌های ارسالی را جعل می‌کند.

- **نوع بسته:** بسته با آدرس مبدأ جعلی.

- **نقاط ضعف:** تمام پاسخ‌ها به آدرس جعلی ارسال می‌شوند، بنابراین شما نتایج را نخواهید دید مگر اینکه مسیریابی را به نحوی دستکاری کنید (Source Routing که اغلب غیرفعال است). نیازمند مشخص کردن رابط خروجی با -e است.

- **ریسک‌های عملی:** بسیار بالا. عملاً نتیجه اسکن را از دست می‌دهید مگر در سناریوهای بسیار خاص.

**مثال:**

```bash
sudo nmap -sS -S 1.2.3.4 -e eth0 10.10.10.10
```

## `--source-port  /g`

- **تحلیل فنی:** شماره پورت مبدأ (Source Port) بسته‌های ارسالی را روی یک پورت خاص (معمولاً ۵۳ DNS یا ۲۰ FTP-data) ثابت نگه می‌دارد. این کار برای دور زدن قوانین فایروال ساده‌ای است که ترافیک از پورت‌های خاصی را مجاز می‌کنند.

- **نوع بسته:** بسته با پورت مبدأ مشخص.

- **نقاط ضعف:** فایروال‌های Stateful و IDS/IPS پیشرفته به راحتی این ترفند را تشخیص می‌دهند.

- **ریسک‌های عملی:** کم.

**مثال:**

```bash
sudo nmap -sS --source-port 53 192.168.1.1
```

## `--data-length`

- **تحلیل فنی:** تعداد مشخصی بایت داده تصادفی به انتهای بسته‌های پروب اضافه می‌کند. این کار می‌تواند باعث گمراهی آنالیزورهای ساده که به دنبال الگوهای بسته‌های اسکن معمولی هستند، شود.

- **نوع بسته:** بسته با payload اضافی.

- **نقاط ضعف:** تأثیر محدود در برابر سیستم‌های پیشرفته.

- **ریسک‌های عملی:** افزایش پهنای باند مصرفی.

**مثال:**

```bash
sudo nmap -sS --data-length 100 10.0.0.1
```

## `--spoof-mac`

- **تحلیل فنی:** آدرس MAC مبدأ فریم‌های اترنت را جعل می‌کند. در شبکه‌های محلی می‌تواند برای پنهان کردن هویت واقعی دستگاه اسکن‌کننده استفاده شود.

- **نوع بسته:** فریم اترنت با MAC جعلی.

- **نقاط ضعف:** اگر اسکن از طریق روتر انجام شود، فقط MAC روتر برای هدف visible است. در LAN، ممکن است توسط کنترل دسترسی پورت (Port Security) شناسایی و مسدود شود.

- **ریسک‌های عملی:** متوسط.

**مثال:**

```bash
sudo nmap -sS --spoof-mac 0 192.168.1.1
```

(MAC تصادفی)

## `--ttl`

- **تحلیل فنی:** مقدار فیلد Time to Live (TTL) در هدر IP را تغییر می‌دهد. می‌تواند برای شبیه‌سازی فاصله (hop count) یا دور زدن قوانین ساده فیلترینگ بر اساس TTL استفاده شود.

- **نوع بسته:** بسته با TTL دست‌ساز.

- **نقاط ضعف:** تشخیص آسان.

- **ریسک‌های عملی:** کم.

**مثال:**

```bash
sudo nmap -sS --ttl 128 10.10.10.10
```

## `--badsum`

- **تحلیل فنی:** یک checksum نادرست برای لایه TCP یا UDP محاسبه و در بسته قرار می‌دهد. از آنجایی که دستگاه‌های معمولی بسته‌های با checksum نادرست را دور می‌ریزند، هر پاسخی که دریافت شود نشان‌دهنده حضور یک سیستم بازرسی (فایروال، IDS) است که بسته را پردازش و پاسخ تولید کرده بدون اینکه checksum را بررسی کند.

- **نوع بسته:** بسته با checksum عمداً خراب.

- **نقاط ضعف:** فقط برای تشخیص دستگاه‌های میانی کاربرد دارد.

- **ریسک‌های عملی:** کم.

**مثال:**

```bash
sudo nmap -sS --badsum 192.168.1.1
```
