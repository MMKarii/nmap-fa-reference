# ۵. Scan Types، انواع اسکن

## `-sS (TCP SYN Scan / Stealth Scan)`

- **نحوه عملکرد:** بسته TCP با پرچم SYN ارسال می‌شود. پاسخ SYN/ACK نشان‌دهنده پورت باز است (Nmap سپس با ارسال RST ارتباط را می‌بندد). پاسخ RST نشان‌دهنده پورت بسته است. عدم پاسخ به معنای فیلتر شده است.

- **نیاز به Root:** دارد.

- **میزان Stealth:** بالا. هیچ connection کامل TCP برقرار نمی‌شود.

- **شناسایی توسط IDS/IPS:** احتمال شناسایی وجود دارد، اما کمتر از Connect Scan.

- **عبور از فایروال:** می‌تواند برخی از فایروال‌های ساده را دور بزند.

**مثال واقعی:**

```bash
sudo nmap -sS 10.10.10.10
```

### مقایسه SYN Scan و Connect Scan

| ویژگی | SYN Scan (`-sS`) | Connect Scan (`-sT`) |
|---|---|---|
| نیاز به Root | بله | خیر |
| Connection کامل | خیر | بله |
| سطح لاگ | کمتر | بیشتر، در هدف |
| سرعت | سریع‌تر | کندتر |

## `-sT (TCP Connect Scan)`

- **نحوه عملکرد:** از سیستم‌کال connect() استفاده می‌کند تا یک connection کامل سه‌وجهه TCP برقرار کند. اگر موفق شود، پورت باز است.

- **نیاز به Root:** ندارد.

- **میزان Stealth:** پایین. connection کامل در لاگ سیستم هدف ثبت می‌شود.

- **شناسایی توسط IDS/IPS:** به راحتی شناسایی می‌شود.

- **عبور از فایروال:** سخت‌تر.

**مثال واقعی:**

```bash
nmap -sT 192.168.1.1
```

## `-sU (UDP Scan)`

- **نحوه عملکرد:** بسته UDP خالی (یا با Payload) به پورت هدف ارسال می‌شود. اگر پاسخ ICMP Port Unreachable دریافت شود، پورت بسته است. اگر پاسخ UDP دریافت شود، پورت باز است. اگر هیچ پاسخی نیاید، پورت open|filtered در نظر گرفته می‌شود.

- **نیاز به Root:** دارد (برای ارسال بسته‌های UDP خام).

- **میزان Stealth:** متوسط (ترافیک UDP رایج است).

- **شناسایی توسط IDS/IPS:** امکان‌پذیر.

- **عبور از فایروال:** بستگی به قوانین دارد.

**مثال واقعی:**

```bash
sudo nmap -sU --top-ports 50 192.168.1.1
```

- **توجه:** UDP Scan به شدت کند است.

## `-sA (TCP ACK Scan)`

- **نحوه عملکرد:** بسته TCP با پرچم ACK ارسال می‌شود. این اسکن برای نقشه‌برداری از قوانین فایروال stateful استفاده می‌شود. پاسخ RST نشان می‌دهد پورت unfiltered است (بسته به فایروال رسیده). عدم پاسخ نشان‌دهنده filtered است.

- **نیاز به Root:** دارد.

- **میزان Stealth:** متوسط.

- **شناسایی توسط IDS/IPS:** احتمال شناسایی وجود دارد.

- **عبور از فایروال:** خیر، هدف اصلی تشخیص وجود فایروال است.

**مثال واقعی:**

```bash
sudo nmap -sA 10.0.0.1
```

## `-sF (FIN Scan)، -sX (Xmas Scan)، -sN (Null Scan)`

- **نحوه عملکرد:** این اسکن‌ها از بسته‌های TCP غیرعادی استفاده می‌کنند:

- **FIN Scan:** پرچم FIN تنظیم شده.

- **Xmas Scan:** پرچم‌های FIN، PSH و URG تنظیم شده (مثل درخت کریسمس).

- **Null Scan:** هیچ پرچمی تنظیم نشده.

- **طبق RFC 793:** اگر پورت بسته باشد، باید RST برگرداند. اگر پورت باز باشد، باید بسته را نادیده بگیرد. بنابراین عدم پاسخ، نشانه پورت open|filtered است.

- **نیاز به Root:** دارد.

- **میزان Stealth:** بالا (غیرعادی).

- **شناسایی توسط IDS/IPS:** بالا (بسته‌های غیرعادی).

- **عبور از فایروال:** ممکن است فایروال‌های ساده را دور بزند.

**مثال واقعی:**

```bash
sudo nmap -sF 192.168.1.10
```

- **نکته:** این اسکن‌ها روی سیستم‌های ویندوز و برخی سیسکوها قابل اعتماد نیستند (این سیستم‌ها ممکن است به پورت باز هم RST بفرستند).

## `-sY (SCTP INIT Scan) و -sZ (SCTP COOKIE ECHO Scan)`

- **نحوه عملکرد:** اسکن‌های مشابه SYN و NULL برای پروتکل SCTP.

- **نیاز به Root:** دارد.

- **میزان Stealth:** متوسط (پروتکل کمتر رایج).

- **شناسایی توسط IDS/IPS:** امکان‌پذیر.

- **عبور از فایروال:** بستگی به پشتیبانی از SCTP دارد.

**مثال واقعی:**

```bash
sudo nmap -sY 192.168.1.1
```

## `-sI (Idle Scan / Zombie Scan)`

- **نحوه عملکرد:** یک تکنیک اسکن پیشرفته و کاملاً غیرمستقیم که از یک میزبان ثالث (Zombie) برای اسکن هدف استفاده می‌کند. با دستکاری شماره توالی TCP Zombie و مشاهده تغییرات آن، وضعیت پورت‌های هدف استنباط می‌شود.

- **نیاز به Root:** ندارد (اما یافتن Zombie مناسب نیازمند دسترسی است).

- **میزان Stealth:** بسیار بالا (منبع ترافیک، Zombie است).

- **شناسایی توسط IDS/IPS:** بسیار دشوار.

- **عبور از فایروال:** بله، اگر Zombie در موقعیت مناسب باشد.

**مثال واقعی:**

```bash
nmap -sI zombie_ip 10.10.10.10
```

- **معایب:** پیچیده، کند، و نیازمند یافتن Zombie با پیش‌بینی‌پذیر بودن شماره‌های توالی و عدم ترافیک فعال.

## `-sO (IP Protocol Scan)`

- **نحوه عملکرد:** بسته‌های IP را با شماره پروتکل‌های مختلف (مثلاً ۱ برای ICMP، ۶ برای TCP) ارسال می‌کند تا پروتکل‌های لایه شبکه‌ای که توسط میزبان هدف پشتیبانی می‌شوند را شناسایی کند.

- **نیاز به Root:** دارد.

- **میزان Stealth:** پایین.

- **شناسایی توسط IDS/IPS:** بالا.

- **عبور از فایروال:** خیر.

**مثال واقعی:**

```bash
sudo nmap -sO 192.168.1.1
```

## `-b (FTP Bounce Scan)`

- **نحوه عملکرد:** از یک سرور FTP معیوب که از ویژگی PROXY یا PORT پشتیبانی می‌کند، برای اسکن غیرمستقیم پورت‌های یک سیستم سوم استفاده می‌کند.

- **نیاز به Root:** ندارد.

- **میزان Stealth:** متوسط (منبع ترافیک، سرور FTP است).

- **شناسایی توسط IDS/IPS:** امکان‌پذیر.

- **عبور از فایروال:** ممکن است.

**مثال واقعی:**

```bash
nmap -b ftp_server:port target_ip
```

- **نکته:** این آسیب‌پذیری امروزه بسیار نادر است.
