# Security Policy

## Scope

This repository contains documentation, publishing automation, and supporting scripts for the bilingual Nmap reference. Security reports for this repository should concern issues in these project files, workflows, generated site behavior, or repository-maintained tooling.

Vulnerabilities in Nmap itself are out of scope for this repository and should be reported to the upstream Nmap project through its official security/contact channels.

## Reporting a repository security issue

Please do **not** open a public issue containing:

- credentials, API tokens, passwords, or secrets;
- real customer or organization identifiers;
- private network inventories, internal hostnames, or sensitive scan output;
- exploit-sensitive details that would create unnecessary risk before a fix is available.

When GitHub Private Vulnerability Reporting is enabled for this repository, use that private reporting channel. If it is not available, contact the maintainer privately using the contact options published on the `MMKarii` GitHub profile and include only the minimum information needed to reproduce the repository issue safely.

## What to include

A useful report includes:

1. the affected repository file, workflow, or published page;
2. a concise impact description;
3. safe reproduction steps using non-sensitive test data;
4. the observed and expected behavior;
5. a suggested mitigation, when known.

## Response expectations

Reports are handled on a best-effort basis. This project does not promise a formal response-time SLA. Confirmed issues will be prioritized according to practical impact and the risk of public exposure.

## Responsible use

Documentation examples are intended for education, administration, labs, and explicitly authorized security assessments. Do not use this repository as a reason to scan systems or networks without permission.
